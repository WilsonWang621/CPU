# 阶段 4：继续尝试 400 MHz

以阶段 3 的 v75 为固定对照：308.71269 MHz、17,754.13250 μm²、IPC 0.8460240059、19/19 正确性。`baseline-v75` 明确复用其已有测量；`measurement_origin` 指向原实验，没有重复宣称新测量。

沿用课程原样 `scripts/synth.py`、ASAP7 RVT TT、默认 2 ns 综合约束，SRAM 计入面积。性能测试内存延迟 20，周期上限 30,000,000。每拍一条发射、一条退休；19 项正确性、IPC ≥0.845、面积 ≤18,000 μm²、频率 >300 MHz 是基准保留条件，本阶段目标为 ≥400 MHz。

v75 的最差路径为 `Dcache tag SRAM -> 响应仲裁/返回 tag -> 操作数唤醒 -> eligible -> 发射 payload 选择 -> 地址加法`。映射网表确认 `_063199_/Y` 是返回 ROB tag 的第 1 位，扇出 105、门延迟 0.6261 ns；`_101981_/Y` 是 `eligible_6`，扇出 75、门延迟 0.3872 ns。末尾地址加法约 0.325 ns。400 MHz 需要最小周期从 3.2392578125 ns 压到 2.5 ns。

本轮首先检验以下方向，配置、源码和 RTL 在各实验目录冻结：

- `issue-slice-bits`：将发射 payload 的局部选择分片由 32 位改为 16 或 8 位。年龄选择、发射顺序和所有流水边界不变；观察局部选择输出的负载和综合面积。
- `banked-return-match`：从各 bank 已寄存的响应归属提前比较 ROB tag，再用实际响应仲裁的单条握手确认匹配。操作数和 ROB 写入仍使用原仲裁器的数据，没有新增 Load 延迟。debug 检查逐 bank 选择与全局握手相等、最多一个 bank 被选中、选中 tag 与数据归属一致，以及每个操作数/ROB 行的匹配与原全局返回 tag 实现一致。
- `local-issue-eligibility`：在每个保留层级的选择分片里，用 `issueAllowed & readyA & readyB` 局部形成最终就绪条件。根调度器使用相同条件决定发射槽，保持最老就绪策略；缩小全局 `eligible` 的使用范围。
- `fetch-head-slice-bits`：只在 8 项取指结果队列中，为各 16/32 位数据分片保留独立的寄存独热头指针。每个副本在非空队列的实际 dequeue 时同步轮转，redirect 与原队列一起复位；flow 空队列透传不轮转。debug 将每个副本逐拍与原二进制头的独热译码比较，确保空/满、停顿和恢复下的队列顺序不变。

`v79-issue-slice16/critical-origin.json` 从原测量网表追溯出新的起点是 `c.fetch.fetched.head[0]`，终点仍是地址寄存器。该追溯仅重新导出名字和综合前寄存器映射，不修改原综合网表或约束。后续的取指队列实验针对这个实际瓶颈，避免仅凭旧路径继续扩大广播逻辑。

表内新测量均通过 19/19 正确性和六项性能测试。v81、v87、v93 是逐 bank 匹配、局部取指头、并行地址的 debug 版本，也通过 19/19 和六项性能；这些版本没有综合，不作为频率候选。它们启用逐拍归属、队列指针和地址一致性断言。

v88 将原 `qvalid && readyA && readyB && loadAllowed && mduAllowed` 改写为先形成 `issueAllowed`、再与操作数就绪组合，逻辑等价但改变了综合输入结构。默认恢复原表达式后，v89 和最后包含所有可选实验的 v94 都重现 v79 的频率、面积及全部性能周期。不能把旧源码的最好综合值套到改动后的源码；最终基准指向实际重新测量的 v94。

本阶段还验证了三项可选实现：

- 每拍执行两次原恢复除法步骤，32 次商位迭代缩为 16 拍。v90 的 `correctness_pi` 从 21,982,878 降至 13,029,299 周期，减少 40.73%；六项官方性能周期完全不变，整核频率下降，因此默认保持每拍一位。
- 对完整执行的除法缓存原操作数、符号模式、已校正的商与余数；相同操作数的 DIV/REM 或 DIVU/REMU 共用结果，命中一拍完成，取消清空缓存，完成标签仍取新请求。v91 的 pi 降至 13,257,463 周期，减少 39.69%；官方 IPC 无变化，整核频率下降，因此默认关闭。
- 分派时同时计算原基值及三路 CDB 候选的 `base+imm`，然后按有效位/tag 选择求和结果。保留本核第一匹配通道优先级。仅加速直接分派路径，保留 IQ 已存指令的地址计算，以限制面积。v92 整核频率下降，没有采用。完整并行 IQ 地址准备需要更多寄存器和加法器，当前面积仅余 215.34 μm²，尚未实现。

MDU 的四种配置（每拍一/两位 × 缓存关闭/开启）通过独立 C++ RV32IM 参考模型，共 76,544 个算术用例、640 次取消/复位；涵盖八种运算、零除、符号溢出、随机输入、商余数共用、符号模式隔离和 ROB tag 重用。缓存配置各观察到 6,004 次一拍除法结果，日志及输入/RTL 哈希见 [MDU 验证](../validation/muldiv/result.json)。并行地址直接对实际 `SourceOperand` 做 Yosys SAT 等价证明，覆盖全部 218 位输入，包括未使用操作数、架构/ROB 来源和多个 CDB 同时匹配，见 [地址证明](../validation/dispatch-address/result.json)。该证明验证地址算术，不声称证明整核。

成对年龄矩阵及下一拍登记发射选择可作为后续实验。本核目前允许当拍 CDB 唤醒、选择并写入执行寄存器，直接登记现有选择会改变 Load 依赖延迟；需同时设计下一状态就绪、旁路和恢复，不能只加一级选择寄存器。取指入队预译码可减少当前 `head -> rs -> rename/ROB 读取 -> 源操作数 -> 地址` 路径，也需要重新核对 redirect 和队列流透传。数据提前准备再发布 valid、寄存恢复位图和局部 BHT 训练在本核已有实现，本轮保留。

最终采用 v94：相对 v75 频率提升 **7.59%**，面积增加 **30.53 μm²**，所有官方性能周期和 IPC 不变。最小周期 **3.0107421875 ns**，距 400 MHz 的 2.5 ns 还需压缩约 **17%**；400 MHz 未达到。课程默认 2 ns 约束下 WNS 为 -1.010498 ns，332.14 MHz 来自原脚本的周期搜索。使用理想时钟且无布线寄生，结果是此课程综合/STA 流程的测量。默认参数、冻结源码、发布 RTL 和 `baseline.json` 统一指向 v94，其他尝试以关闭的可选参数和冻结报告保留。

交付前逐项核对 16 次新实验的源码/RTL 哈希、综合输入哈希及全部 19+6 项测试结果，确认可编辑源码与 v94 冻结源码完全一致，默认 RTL 与已测文件字节相同；见 [制品核对](artifact-verification.json)。`make generate` 从 v94 冻结源码成功重新生成等价电路，见 [重新生成日志](v94-final-source-slice16/baseline-regeneration.log)。另以可编辑源码直接 `sbt run`，不覆盖任何 CPU 参数，生成电路也与 v94 相同，见 [默认源码生成日志](v94-final-source-slice16/default-source-generation.log)。电路比较只去除注释及空白，发布 RTL 仍保持已测文件的确切字节。v94 单独追溯的 [关键路径起点](v94-final-source-slice16/critical-origin.json) 也确认是取指结果队列的 `head[0]`。
