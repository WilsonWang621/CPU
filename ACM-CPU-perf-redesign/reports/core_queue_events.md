# 核心队列写事件拆分

`next_state` 原来在重命名、退休和请求接受的多层条件中传递整个 IQ/LQ/CSB
记录数组。现在只传递需要同拍观察的控制位，并生成有限的分配写事件；每个
固定物理条目按原优先级更新数据。仍允许同周期释放再分配、多个提交 Store、
Load 取消以及返回与唤醒前递，没有增加流水停顿。

相同精简四路配置的独立 core 粗粒度综合中，mux 输出位总和从 1,024,737
降到 674,488（减少 34.18%）；3104 位整 LQ、2160 位整 CSB、984 位整 IQ
选择器分别从 40/60/24 个降到零，寄存器位数保持 26,688。
这衡量中间展开，不能代替最终标准单元面积。

16 项核心、76 项 LSU 和 6 项性能测试全部通过。与各冻结基线逐项比较的
周期、事务、覆盖以及所有非主机运行时计数完全一致；性能配置仍为
374,104/342,543=1.092137 IPC。默认配置及非二次幂容量的双宽配置均通过
严格 lint。完整参数、源码/二进制哈希和对照结果见
[验证记录](data/core_queue_events.json)。

该改动消除了队列数据更新的无谓规模；年龄仲裁中的串行比较链仍需要
单独处理，不能由本项结果推断 300 MHz 已经达标。
