# B 角色个人实施规划：前端与系统服务

> 更新于 2026-09-27。本人承担 B 角色。以[双人分工](project-ab-plan.md)的 B1～B8、[八周计划](eight-week-two-person-plan.md)和[执行清单](todo.md)为准；本文只细化个人执行顺序，不改变 A/B 模块所有权。日期沿用八周计划的暂定日历。

## 职责与交付

我的主责是 PC/预测、取指缓冲、RV32IM 硬件译码、I-cache、D-cache、统一内存仲裁与课程接口、八种 M 指令的 MDU、Top、构建评测工具，以及这些模块的测试、参数实验和参数敏感度报告。D-cache 包括掩码写、脏行替换、写回和程序结束时的排空。

我向 A 提供完整译码包、D/MDU 事务服务及响应；接收 A 的重定向和提交时预测训练。A 负责 AGU/LSQ、Store Buffer、访存顺序、事务 ID 与迟到结果筛选，并维护独立 ISA 参考模型和提交对拍。公共类型代码由 A 维护，接口字段和语义由双方共同冻结。完整责任及初始点数见[双人分工](project-ab-plan.md)：B1～B8 合计 **100 相对点**，不是已投入工时。

仓库已有课程评测框架、Chisel 模板及部分开发中的整数执行代码；这些成果不能直接视作 B1～B8 已完成。先逐项核对现有生成、仿真和评测入口，记录能够复现的命令、结果与缺口，再领取尚未完成的 B 任务。清单中的任务保持未完成，直到对应验收通过。

3. **并行建立服务测试入口。** 用事务发生器、软件字节内存及可配置延迟模型驱动 D 端口和 MDU；先测请求/响应保持、随机背压、掩码写及事务 ID 原样返回，再接真实 Cache 与统一内存仲裁。

## 与 A 的交接规则

- **前端边界：** 我在 `ready=0` 时保持完整译码包；收到 A 的重定向时按共同确定的优先级取消旧路径包，并排空旧 IF 请求、丢弃旧响应。预测训练由 A 在提交时发来，我负责缓存预测表更新和训练队列背压。
- **数据边界：** A 发送已提交 store，并负责地址对齐、移位数据与字节 mask；我按 D 口事务执行访问，返回原样 `txnId` 和响应。写确认表示后续 D 口访问可见，最终主存一致性以排空完成为准。
- **集成定位：** A 用独立模型和提交轨迹定位首个架构差异；我检查前端、Cache、仲裁、MDU 与 Top 响应。缺陷由对应模块负责人修复。双方共同验证恢复、迟到响应、I/D 竞争与结束排空。
