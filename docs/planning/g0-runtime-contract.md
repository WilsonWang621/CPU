# G0：当前框架的启动、内存与退出契约

本文记录本仓库**现有课程框架**已经确定的外部行为，供前端、后端和 Top 对接使用。依据为 `scripts/sim.cpp`、`docs/axi4-lite.md` 和当前测试镜像；它不替代尚需 A/B 共同确定的内部接口。

## 启动与程序装载

- `student_top` 使用高电平同步复位；仿真器在启动时保持复位 5 个时钟周期，然后释放。
- 仿真器将 `program.data` 的十六进制字节按 `@address` 标记装入小端 RAM；未装载的字节为零。当前仓库所有正确性和性能镜像的首个装载地址均为 `0x00000000`，示例程序的 `_start` 也在此处。因此当前镜像的前端复位 PC 取 `0x00000000`。仿真器本身不向 CPU 传入入口地址；若以后换镜像或评测版本，须重新核对入口。
- RAM 地址范围为 `0x00000000`–`0x0fffffff`，容量 256 MiB。取指与数据访问最终使用同一外部 RAM。

## Top 与 AXI4-Lite 边界

- 顶层模块名固定为 `student_top`，端口见 `chisel/src/StudentTop.scala`。CPU 是 AXI4-Lite master，外部 RAM 是 slave。AR/R、AW/W/B 五个通道分别用 `valid && ready` 在时钟上升沿完成交接。
- 32 位总线地址必须 4 字节对齐。CPU 的字节/半字访问由内部生成对齐字地址、写入字节 lane 和 `wstrb`；外部 RAM 不接受非对齐的总线地址。
- AW 和 W 可以在不同周期交接；master 在各自交接前必须保持 `valid` 和载荷稳定。写入只有在 AW、W 都被接收后才会服务。读响应和写响应也必须分别完成 R、B 通道交接。
- 仿真从机的各通道队列深度为 16；新接收的请求最早下一周期服务。当前 `Makefile` 默认 `LATENCY=10`，可通过命令行调整。规划文档中的 3/20 周期是早期评测假设，不能当作当前框架的固定时序；性能实验应明确记录实际 `LATENCY`。
- `rresp`/`bresp` 的 `00` 表示成功，`10` 表示对齐或退出写掩码错误，`11` 表示地址译码错误。Top 和服务模块不能把错误响应当作正常数据/写确认。

## 退出与排空

- 程序以对 `0x80000000` 的 32 位 store 退出：`awaddr=0x80000000`、`wstrb=0xf`，`wdata` 为返回值。退出地址是 MMIO，不属于 RAM。
- 仿真器在这笔写的 **B 通道交接** 时结束运行并读取返回值。因此最后的退出写必须在所有需要对外可见的较早写入、Cache 脏行写回和下级请求完成后才发出；仅在内部标记“已提交”不足以保证外部内存已经更新。
- 在最终退出写的 B 响应到来前，Top 必须持续接收响应，不能提前停钟或停止协议排空。
